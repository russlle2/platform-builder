# Preview before contact details

A personal preview now starts with a business name, a supported industry and an optional short description. Private account and public website email fields are available in an optional contact section. Entered addresses must be valid, and both addresses remain required at the existing plans/checkout boundary. Phone, service area, owner name and other details remain optional. No account or checkout security rule changed.

A draft without an account email stays in the current browser tab; it does not create an anonymous contact record or send failing lead requests. Supplying a valid account email permits the existing progress-checkpoint saves before purchase. The form explains that condition and retains the separate, unchecked news/offers choice. New checkpoints use notice version `preview-followup-2026-10-24`; existing records are not rewritten. If a visitor removes the account email and continues, the previous save status is retired and late responses cannot claim that the newer local-only details were saved remotely. Previous server records are not deleted.

Primary wizard actions use dark botanical teal with white text for readable contrast. The style step includes a responsive illustration driven by the same color, font and structure resolvers used by the preview request. It uses only the business name, tagline and description, never the private account email. Tone examples are labeled sample wording and do not rewrite supplied business text. Original colors use a clearly labeled neutral illustration because the chosen template determines those colors. Saved custom colors/fonts retain precedence and are labeled accordingly. The illustration is not a certified template preview or a promise about every page's rendering.

The existing Customize action opens the editor immediately and presents a loading or retry state while the preview responds. Browse now distinguishes a failed catalogue request from an empty result, keeps existing cards after pagination failures, and retries the same next page. Catalogue requests time out after 20 seconds with recovery. Existing request-generation guards still prevent old personal browse responses from replacing sample choices or clearing a newer loading state.

The readiness panel continues to describe completeness of supplied details and style choices. It does not certify credentials, booking functionality or enquiry outcomes, and no invented score improvement is promised.

Verification covers optional-email validation, saved drafts/custom themes, sample isolation, reactive style direction, private/public checkout identity, delayed preview errors, initial and paginated browse errors, stalled browse requests, and completed/delayed prior-save status. Browser APIs use explicit local fixtures; these checks do not establish real provider payments, email delivery or published-release success.
