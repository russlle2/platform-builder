Contact page — quick notes and testing guide\n\nFiles in this chunk:\n- contact.html  — interactive contact + tools page\n- README.md     — this file\n\nPurpose:\nThis contact view is built for a membership-focused wellness coach site. It includes two local interactive tools: a Mood-to-Method selector and a 30-day Progress Path preview. The page uses only local HTML/CSS/JS; no external resources are required. Placeholders for site-wide values are present as tokens ({{BUSINESS_NAME}}, {{TAGLINE}}, {{PHONE}}, {{EMAIL}}, {{PRIMARY_CTA_LABEL}}, {{PRIMARY_CTA_URL}}, {{CITY}}, {{STATE}}).\n\nKey interactions to test:\n1) Mood-to-Method selector\n   - Click any mood tile in the "Mood right now" area.\n   - The "Method snapshot" area updates with a short approach description.\n   - The primary CTA button text morphs to a mood-specific CTA. Clicking it simulates sending the visitor to the membership signup URL ({{PRIMARY_CTA_URL}}) with the mood appended as a query parameter.\n\n2) Progress meter (30-day Path Map)\n   - Select up to 3 goals from the Goals list (buttons). Attempts to select more than 3 will result in a brief UI hint.\n   - Click "Preview 30-day path". The right column will render a four-week map, distributing micro-tasks across weeks tailored to the selected goals.\n\n3) Form and CTA flow\n   - Fill in Name and Email (email is required for the lightweight demo).\n   - Choose mood and goals if desired.\n   - Click the primary CTA. The page will show a confirmation alert summarizing the plan intent and then redirect to {{PRIMARY_CTA_URL}} with mood metadata in the query string. This is a simulated flow (no server calls).\n\nDeveloper notes:\n- All logic lives in contact.html within the <script> tag. The page avoids external dependencies and keeps the state minimal.\n- Goals and moods are defined at the top of the script to make copy adjustments straightforward.\n- The form intentionally prevents real submission; replace the simulated redirect with an actual API call if you wire this into a backend.\n- Placeholder tokens should be replaced by the build system or server-side templating before publishing.\n\nAccessibility considerations:\n- Buttons and inputs use standard HTML controls; add ARIA labels if you expand the interactive SVG visualization.\n- The right-hand "method snapshot" uses aria-live="polite" to communicate changes for assistive tech.\n\nStyling\n- Visuals are achieved with pure CSS and an unobtrusive glass-panel aesthetic; tweak variables at the top of the <style> for theme updates.\n\nIf you need an assets folder (pattern SVG) created for other pages, add assets/img/pattern.svg as a lightweight decorative SVG. This chunk intentionally keeps the contact page self-contained.
